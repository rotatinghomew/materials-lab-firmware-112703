# 固件上线人员身份与审批证据

厂商发布、线站确认、设备安装窗口和回执的本地资料以 JSON 保存，全部身份、系统与输入均为合成。资料服务只回放各参与方提供的事实。

需要 Python 3.11 和 OpenSSL 3。运行 `python3 -m unittest discover -s tests -v` 核对项目资料和本地接入（隔离模式 `python3 -I -m unittest discover -s "$PWD/tests" -v` 同样可跑）。运行 `python3 replay.py` 启动回放服务，默认监听 `127.0.0.1:8765`。访问 `/streams` 查看资料名称，`/streams/名称` 读取相应资料，`/timeline?through=60` 读取截至演练时刻 60 收到的事件。也可直接读取 `data/` 中的原始文件。

签名来源的核对使用 OpenSSL 3。

## 资料约定

identities 的 subject 在其 authority 内唯一，person 是双方各自确认后用于判断同一人的设施编号。packages 的 artifact 路径指向合成文本工件，字节用于核对厂商材料，仿真节点不会加载执行。节点时间窗左闭右开。timeline 提供厂商、值班和设备节点分别产生的记录，设备接受与开始是两个不同的状态。
厂商发布证明位于 proofs，*.json 为签名覆盖的原始字节，*.sig 为 Ed25519 二进制签名，签发公钥在公开目录中。清单列摘要和包号，登记记录仍要校对发布人所属单位。记录中的时间用本地演练时钟。

## 放行工作台（workbench/）

在只读来源之上构建的双边授权放行工作台：把厂商证明、设施批准、实验窗口和节点
回执串成一条可逐台复查的身份—批准—执行链。来源资料永不回写，设施方的全部动作
追加到独立的 JSON Lines 日志（默认 `workbench_state/journal.jsonl`，已在 .gitignore），
服务重启后从“来源事实 + 工作台日志”确定性重建同一状态。

启动：

```
python3 run_workbench.py serve                      # http://127.0.0.1:8766/
python3 -m workbench.server --source-through 40     # 历史演练：只纳入 t<=40 的来源事件
```

终端用法：

```
python3 run_workbench.py status --at 60 --node N12 --image IMG-9B
python3 run_workbench.py apply --kind facility_approve --actor F-12 \
    --facts '{"image":"IMG-9C","group":"G2"}'
```

### 界面四个面板

1. 工艺负责人视图：分设备 × 包的阶段、可执行状态、失效依据与可办动作；
2. 合规逐台复查：13 项依据逐项给出 通过/失效/不适用、证据与处置建议，含链上历史事件；
3. 办理台：批准、暂停/恢复、安装计划/撤销、节点四类回执、核销、信任冻结、人员停用；
4. 合并事件流：来源只读事件与工作台追加事件分来源标记，可拖动时钟回放任意时刻。

### 强制执行的规则

* **双边授权**：厂商身份只证明来源与所签字节；部署授权必须由当前值班组按
  设备 + 内容摘要 + 设备状态作出。厂商侧任一依据失效时，设施批准直接被拒。
* **按包号与摘要绑定**：IMG-9B 与 IMG-9C 同为 2.1.5、同名 `controller.bin` 但摘要不同，
  批准与回执按包号绑定，不能按文件名/版本号挪用旧批准。
* **职责分离**：提交该版本的同一自然人（P8 同时拥有厂商 acct-a 与设施 F-88）
  不得为设施方作同一次独立批准。
* **失效证明不采信**：签名失败、摘要与工件字节不符、签发主体未登记或已停用、
  信任域冻结，均判失效并给出对应处置。
* **变化按对象重判**：批准人离组只影响其批准的链，文件变更只影响该包，
  信任冻结只影响该信任域，其他节点结论不变。
* **暂停语义**：未开始节点不能凭旧接收回执启动；已开始且不宜强停的节点
  只允许 finish 或本节点 rollback，之后才能核销。
* **计划撤销隔离**：撤销上一安装计划不产生任何新版本授权，
  同节点的其他包仍须独立批准与计划。
* **当班权限**：实际接收/安装人必须持安装角色且未离组；时间窗左闭右开，
  窗口外不得换固件。

### HTTP 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/state?at=N` | 全部节点×包状态与 13 项依据（at 可回放历史时刻） |
| GET | `/api/case?node=&image=&at=` | 单台逐依据复查 |
| GET | `/api/events` | 来源 + 工作台合并事件流 |
| GET | `/api/journal` | 工作台追加日志 |
| POST | `/api/apply` | 办理 `{kind, actor, facts, at?}`，违规返回 409 与中文原因 |

模块划分：`workbench/crypto.py`（OpenSSL 验签与摘要）、`sources.py`（只读加载与
证明核对）、`journal.py`（追加日志与事件归一化）、`policy.py`（重放与逐依据判定）、
`service.py`（办理校验与状态转移）、`server.py` + `static/`（HTTP 与单页界面）。
